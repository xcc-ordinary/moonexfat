# moonexfat

Pure-MoonBit **exFAT filesystem image parser** — no mount, no root, no FFI.
Built from the public [Microsoft exFAT specification][spec], cross-checked
against `exfatprogs` and the Linux kernel exfat driver.

exFAT is the standard format of SDXC cards and most USB flash drives.
The MoonBit ecosystem already has FAT12/16/32 ([moonfat][moonfat]),
NTFS + ext4 ([moonfs][moonfs]) and ISO 9660 ([mooniso][mooniso]) parsers —
**exFAT was the missing member of the family.** moonexfat fills that gap.

## Status (v0.2.0 — weeks 1–2)

- ✅ **Main Boot Sector parsing** with spec-level validation: JumpBoot,
  `EXFAT   ` signature, MustBeZero region, sector/cluster shift ranges,
  FAT geometry consistency, cluster-count / root-cluster bounds,
  volume-length containment, revision check.
- ✅ **Boot Checksum** (spec §3.4): rotate-right accumulate over sectors
  0–10, excluding the mutable `VolumeFlags` / `PercentInUse` bytes;
  every 4-byte repetition in sector 11 is verified.
- ✅ **Full boot-region verification** (sectors 0–11) including the
  0xAA55 signature of all 8 Extended Boot Sectors.
- ✅ **FAT cluster chains** (spec §5): entry classification, chain walking
  with cycle / bad-cluster / invalid-entry detection.
- ✅ **Allocation Bitmap** (spec §7.1): bit addressing, allocated count
  with padding-bit masking.
- ✅ **Up-case Table** (spec §7.2): TableChecksum verification, ASCII
  mapping rule, 0xFFFF rejection, case mapping for names.
- ✅ **Root-directory scanning**: locates the Allocation Bitmap (0x81),
  Up-case Table (0x82) and Volume Label (0x83) entries; skips file entry
  sets via SecondaryCount.
- ✅ **`Volume::open`**: boot → FAT → root chain → bitmap + up-case,
  end to end on an in-memory image.
- ✅ Structured, per-constraint errors with readable messages.
- ✅ `inspect` / `chain` CLI.
- ✅ 52 tests green on `wasm` and `wasm-gc`; checksum tests assert
  **independently computed vectors** (`0x829BD81D`, `0x46987370`,
  `0x88E38EE3`), not self-consistent ones.

## Quick start

```sh
moon update
moon test --target wasm          # 52 tests
moon run cmd/moonexfat --target wasm -- inspect testdata/mini.exfat
moon run cmd/moonexfat --target wasm -- chain testdata/mini.exfat 2
```

Output:

```
exFAT boot region OK (main, sectors 0-11, checksum verified)
  sector size        : 512 bytes
  cluster size       : 512 bytes
  volume length      : 512 sectors
  ...

volume metadata OK:
  volume label       : TEST
  root dir chain     : 2 -> EOC
  allocation bitmap  : 3 / 484 clusters allocated
  up-case table      : 128 entries, checksum verified
```

Corrupt one byte of the checksum sector and the same command reports:

```
boot region INVALID: boot checksum mismatch: expected 0x829bd81d, found 0x829bd800
```

Fixtures (both generated by independent scripts, layouts mirrored in the
whitebox tests): `testdata/synthetic.exfat` (6 KiB boot region) and
`testdata/mini.exfat` (256 KiB full mini volume with FAT, root directory,
allocation bitmap and up-case table).

## How it differs from neighboring projects

- [moonfat][moonfat]: FAT12/16/32 volume codec (in-memory, read/write).
  exFAT is a different on-disk format (directory entry sets, allocation
  bitmap, up-case table) — not covered by moonfat.
- [moonfs][moonfs]: NTFS 3.1 + ext4 image parser. No exFAT support.
- moonexfat: read-only exFAT image parser, spec-driven validation with
  structured errors, targeting native / JS / WebAssembly.
